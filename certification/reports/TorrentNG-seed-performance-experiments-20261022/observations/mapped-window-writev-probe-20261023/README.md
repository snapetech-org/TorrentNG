# Mapped-window plus vectored-write probe — 2026-10-23

**Status: no production change.** A small Linux loopback probe compared buffered `pread` plus Piece-frame `writev` with a read-only 1 MiB mmap window plus the same Piece-frame `writev`. The mapped path did not show a stable CPU improvement once socket output was included; it did not measure process memory or TorrentNG's scheduler and rate-control costs.

The fixture was 64 MiB, generated by the included C program and verified as SHA-256 `265ef5314d5eb8672777efe3256a6c9d884e6fe6686070efaaaca60324ae19bd`. Each method sent four passes (256 MiB total) per round. Both paths emitted eight legal 16 KiB Piece frames per 128 KiB batch through the same vectored writer. The `pread` path reused one 128 KiB buffer; the mapped path mapped one aligned 1 MiB piece window and unmapped it after sending that window. The receiver verified the complete framed byte stream against the same rolling hash in every run.

## Counter-balanced results

The final screen alternated which method ran first. CPU time is for the sending thread only, normalized by the 256 MiB payload. Paired values below are mmap relative to `pread`.

| Round | Order | mmap CPU-s/GiB | pread CPU-s/GiB | mmap change |
|---|---|---:|---:|---:|
| 1 | mmap, pread | 0.437571 | 0.384615 | +13.8% |
| 2 | pread, mmap | 0.299380 | 0.324206 | -7.7% |
| 3 | mmap, pread | 0.299704 | 0.344855 | -13.1% |
| 4 | pread, mmap | 0.352342 | 0.348129 | +1.2% |

The independent medians were 0.326023 CPU-s/GiB for mmap and 0.346492 for `pread`, but the candidate lost in two of four paired rounds. Mean CPU was 0.347249 vs 0.350451 CPU-s/GiB, less than a 1% difference. That variation does not justify adding mmap ownership and truncation handling to the production seed path.

An initial three-round pass accidentally ran mmap first every time. Its raw output is retained in [`results-initial-order-biased.csv`](results-initial-order-biased.csv), but it is excluded from the decision. The counter-balanced output is [`results-counter-balanced.csv`](results-counter-balanced.csv); the exact probe source and build command are also included.

This is a hot-file transfer microprobe, not a whole-client benchmark. It excludes Tokio readiness, the engine scheduler, cancellation, rate admission, cold-page faults, peer fairness, and PSS/RSS measurement. The earlier mapped-read-only probe's 8.6% read-stage reduction therefore remains subsystem evidence; it did not predict a stable socket-path CPU gain. A production mapping would also need to handle external file truncation safely, since accessing a truncated mapping can terminate the process with `SIGBUS`.
