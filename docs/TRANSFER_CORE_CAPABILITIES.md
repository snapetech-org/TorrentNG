# Transfer Core Capability Matrix

This matrix separates the code that exists today from the shared-core
integration and the evidence needed to qualify it. Clean merged `main` commit
`b1f0120855af86f9f9256b5e4f6bdf4bd02d9593` passed the full workspace suite on
Rust 1.94.0 and 1.88.0 (2,298 passed, 0 failed, 12 ignored on each toolchain),
all 20 transfer-rebuild Python regressions, and Clippy (exit 0 with warnings).
Older row wording such as “await bulk pass” describes the earlier status and
is superseded for source-suite execution by the dated validation record in
[`TRANSFER_CORE_ACTIVE_SPECS.md`](TRANSFER_CORE_ACTIVE_SPECS.md#bulk-validation-2026-10-18).
Hosted workflow execution, hardware/storage qualification, crash-cut testing,
live parity, and matched-client evidence are still open; no release capability
or efficiency claim follows from the source-suite pass.

## Evidence labels

- **Integrated and tested**: the production route uses the capability and the
  required repository tests or probes passed on the exact revision.
- **Present, unqualified**: source and any regression tests are written, but
  this rebuild's bulk pass has not run.
- **Integration pending**: the pure module exists, but production actors still
  use the reference implementation.
- **External qualification**: the code is repository-owned, while its required
  hardware, public-network, real-device, long-soak, or hosted evidence is not
  available in this worktree.
- **Deferred**: no capability claim is made and rollout remains disabled or
  on the reference path.

The work-package status and findings register in
[`TRANSFER_CORE_REBUILD.md`](TRANSFER_CORE_REBUILD.md) remain authoritative for
ticket-level progress. This matrix is a capability-oriented view; it does not
turn implementation into qualification evidence.

The final rollout evaluator is available as
`scripts/transfer_rebuild/rollout_gate.py`. Qualification wrappers are created
with `qualification_record.py`, included as hashed artifacts in the
source-bound manifest, and referenced from a strict rollout evidence index.
The evaluator blocks on dirty or mismatched sources, missing artifact kinds or
check IDs, incomplete candidate protocol coverage, or insufficient paired
samples. It never converts a descriptive scorecard into a performance pass;
numeric threshold adoption remains open in D1.
